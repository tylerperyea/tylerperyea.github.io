    ⚡ Short Link — Privacy Notice

    Creating a Short Link uploads a compressed copy of your entire project's source code to the FORGE server, where it is stored and accessible to anyone with the link.

    ⚠️ Do not use Short Link if your project contains sensitive information such as API keys, passwords, internal data, PII, or proprietary code. Use the Long Link option instead — it stores nothing on the server.

    Managed Short Links expire automatically. The server default is preselected; choose another future date and time if needed.

    ⚙ Manage Short Link

    This changes the managed Short Link metadata only. It does not rename or modify the project in the IDE.
    Choose a future date and time. Updating expiration does not re-upload or alter the shared project payload.
    Delete Short Link
    Request that this managed Short Link be made unavailable. Depending on deployment policy, the request may be applied immediately or routed for review. This does not guarantee immediate physical deletion of the immutable project payload.

    📤 Push to GitLab

    Enter a project manually or browse repositories available to your token.
    ℹ️ Creating a repository requires a PAT with api scope. GitLab creates a minimal README commit to establish the requested default branch; FORGE then replaces that bootstrap content with the current VFS.
    ⚠️ Pushing to an existing branch appends a new commit. All VFS files will be created or updated; no history is rewritten.
    ⚠️ Files on the remote branch that are not in your current VFS will be deleted in this commit.
    These files are useful if your team uses the FORGE CLI, but may clutter repos that don't.
    Click "🔍 Preview Changes" to compute the diff against the remote branch.

    GitHub Sharing Credential

    Enter the credential for the configured untrusted GitHub inbox. It is used only by this trusted FORGE IDE page and is never added to the project, inbox packet, URL, or exported files.

    Leave unchecked to keep the credential in memory only until this page is reloaded.

    The inbox credential should have authority only over the disposable request inbox. It must not be able to publish trusted shares.

    Git Share Processor

    Process requests from the configured Git inbox into the trusted share repository. This panel appears only when enabled by deployment config and opened with ?admin=true.

    Work in progress: the processor currently attempts to process every inbox request automatically. Configurable accept, reject, and manual-review policies have not been implemented yet.
