The idea

The old rule is incomplete.

Good, quick, and cheap really can pull against one another. But the way we build changes those tradeoffs. Shorter feedback loops, shared understanding, and fewer handoffs make it easier to improve all three.

Building together does not make the tradeoffs disappear. It helps move them in the right direction.

From zero to shared app in 10 minutes

Here's the fastest path to building and sharing something real. All you need is Chrome and access to Elsa.

2
Build something with Elsa
Ask Elsa to write a multi-file app, then parse it with one click
3
Open a new Elsa chat, and launch the Forge Code Bookmarklet
No special workspace or setup needed just start a fresh chat. FORGE CODE already knows how to read whatever Elsa writes. The bookmarklet will tell Elsa how to write code that it undersands. You can write your prompt directly in elsa, or you can write it in FORGE CODE's prompt box. A good thing to try is a game. Puzzle games are simple, self-contained, and are a good way to get familiar with how the process works. Try something like: 
"Build me a sliding puzzle game with a 4x4 grid, a move counter, and a win condition."
Or try a crossword puzzle, a Jeopardy-style quiz, a Minesweeper clone, a data visualization, or anything else you're curious about. The more specific you are, the better the result.
4
When Elsa finishes, click "Apply Steps" in FORGE CODE
It will scan Elsa's response, find all the code blocks, and show you a summary of what it found. It will put the code into a "virtual file system", which is just in the browser for you only.
5
Click "Preview & Share in FORGE IDE"
This sends your project straight to the full IDE where you can browse files, edit, preview, and share. The project payload itself stays client-side: it is compressed into the URL fragment after the "#" mark, which the browser uses without sending that fragment to the server. The IDE may still make its own configuration or identity requests. Your project is uploaded only when you intentionally create a server-backed Short Link.
3
Share your app
Get a link anyone at FDA can open in their browser
6
In the IDE, create a Short Link
This stores a server-backed copy of the project and creates a compact link that opens it directly in the browser — no install needed for the person you're sharing with. You'll see a privacy notice and can choose an expiration time before creating the link.
7
Paste the link wherever you need it
Teams chat, email, a ticket — the link opens the live app. If you want a self-contained link that stores nothing on the server, use Long Link instead.

4
Sync with your local machine
Optional — for when you want to edit locally, use git, or work offline

The FORGE CLI brings forge in and forge out to your terminal. These two commands let you move a project between the IDE and your local file system in seconds — no manual copy-paste of individual files.

📥 IDE → Local machine
Copy the project JSON from the IDE, then extract it to a local directory.
  1. In the IDE: Ctrl+Shift+C (or Export ▾ → Copy JSON)
  2. On your machine, navigate to your target directory
  3. Run: 
    forge in
forge in reads from your clipboard by default. It will ask before overwriting existing files.
📤 Local machine → IDE
Package your local directory back to JSON, then paste it into the IDE.
  1. In your project directory, run: 
    forge out
  2. In the IDE: Ctrl+Shift+V (or Import ▾ → Paste JSON)
forge out copies to your clipboard automatically. Use a .forgeignore file to exclude node_modules/ etc.

FORGE now has some identity groundwork, but it is not a general SSO API for prototype code. On supported deployments, the IDE can obtain native FORGE identity or discover the current FDA email from GSRS. Preview apps may read that normalized identity through a narrow compatibility endpoint: local GET requests whose path ends in /whoami or /whoami.cfm are answered with FORGE's person object (email, and when available fullName and identifier). No SSO cookies or FORGE authentication headers are exposed to the preview. This identity is a convenience for application UI, not proof of authorization; authenticated application and server-side access controls still depend on the deployment model.
The IDE itself works in any modern browser (Chrome, Edge, Firefox, Safari). However, the FORGE CODE bookmarklet works best in Chrome at FDA. Edge may have issues with bookmarklet drag-and-drop. If you're just using the IDE directly (not the bookmarklet), any browser is fine.
By default, your project stays in the browser-side virtual file system. Editing and previewing do not upload the project payload, although the IDE may make ordinary requests for its own configuration or identity metadata.

Long Link: your project is compressed and embedded directly in the URL fragment. The project is not stored server-side by FORGE.

Short Link: a compressed copy of your project is stored on the FORGE server. Managed Short Links have bounded expiration and show a privacy notice before creation. Don't use sharing features for information that is not appropriate to place in the resulting link or server-backed share.
They're designed for different moments in the workflow, and they're better together than either is alone.

FORGE CODE is a bookmarklet that lives in your browser and runs on any webpage — including Elsa. Its home is the LLM conversation: you ask Elsa to write or modify code, FORGE CODE parses the response, applies the changes to a virtual file system, and lets you preview the result without ever leaving the chat. It's built for the fast, iterative "ask → apply → see → ask again" loop.

FORGE IDE (this app) is where you go when you want to do more with what you've built: browse and edit files, preview across pages, share via URL, push to GitLab, or hand the project off to someone else. It's built for the moments after the LLM conversation — reviewing, refining, and shipping.

The handoff between them is one click in either direction. FORGE CODE has an "Open in FORGE IDE" button that sends your current project straight here. FORGE IDE projects can be exported as a JSON payload and loaded back into FORGE CODE for another round of AI-assisted editing. They're two parts of the same loop, not two separate tools.
The IDE can store and edit any text file, including Python and R scripts. However, the live preview only runs HTML/CSS/JavaScript — it can't execute Python or R in the browser. You can use the IDE to manage and share the source files, then run them locally after extracting with forge in. Python and R execution in the browser (via Pyodide and WebR) is on the roadmap.
